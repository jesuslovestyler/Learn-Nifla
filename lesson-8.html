Lesson 8 — Standing on its own

Step 1: compiling

So far, nifla has run every program: it checks the program, then interprets it, line by line, itself. That is the kindest way to learn — but a program you want to hand to someone should stand on its own. That is niflac's work: it checks the program the same way, then compiles it into a program of its own, which runs with no interpreter beside it:

./niflac greeter.nifla -o greeter
./greeter Ada Byron

Compiled programs behave exactly as interpreted ones — same words, same refusals, same output — because the checker and the meaning are shared. (This book's proof holds every example to that: each is run both ways, and the outputs must agree.)

Feel what just happened, because it is the second half of the promise this book made in its opening. The words did not change — not one letter. What changed is what stands underneath them: the interpreter stepped aside, and the program now stands on its own, checked ahead of time and built to run at full strength. Written like JavaScript; running like Swift. Same language, both halves — and you have now held each one.

Step 3: how a program ends


A standalone program also reports how it ended. When a program simply finishes, it hands back the number 0 — the number for "all went well". exitwith(code) ends a program early, handing back a number of your choosing; any number but 0 says something didn't go as hoped, and whoever ran your program can ask for the number and act on it:

The second say is never reached, and the 3 travels back to whoever ran the program. Lesson 9's doorman uses exactly this honesty: feathercheck answers 0 for a true card and 1 for a false one, so a script can ask "was it true?" without reading a word.
