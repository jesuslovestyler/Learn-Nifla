Lesson 4 — Making your own tools

Step 1: a stretch of code with a name

The toolbox tools were always there. The moment a program grows past a page, you start wanting tools of your own: a stretch of code with a name, that you can hand values to and that hands one value back. That is a function, and make builds one. give is how a function hands its answer back:

The name in the parentheses is the function's parameter — its own shelf, filled fresh by whoever calls it. One function, any number of calls, each with its own filling.

Putting it together: tools calling on tools


Functions that call on other functions are how big programs are built out of small, trustworthy pieces:

You have been writing a library without being told: greet, twice, line, average are your toolbox now, and any program you write can carry them at its top and call on them below. That is the whole secret of large programs — they are small programs, kept in functions, all the way down.


One thing to keep in your pocket: a function that reaches its end without give hands back nothing at all. The next lesson makes that matter.

Two things to notice. addgift never says give — it does its work by growing the list it was handed (lists are shared: a change made through one name is seen through every name), and hands nothing back. And total walks the same list the Lesson 2 thread walked — but now the walk has a name, and the book will never have to write it again.

You can now…


  • build a function with make, hand it values through


  parameters, and hand an answer back with give;


  • put loops and lists inside functions, each call with


  fresh shelves of its own;


  • grow a personal library of tools and build programs


  out of them;


  • add to a shared list from inside a function that


  gives nothing back.
