Lesson 5 — Kinds and nothing

Step 1: saying the kind out loud

Every value is of one kind: number, text, boolean, list, object, or bytes — and there is one more, nothing, which gets Step 2. A kind can be written, as a mark: a kind word after a colon, on a let, on a function's parameters, or after -> on a function to say what it gives. A mark is a promise the language checks — at every boundary the value must be of the marked kind, or the program is refused in plain words:

Step 2: nothing, and maybe


nothing is a value: the value that says there is nothing here. It can be kept, handed around, and compared, and it speaks as nothing. Why would a program hold nothing on purpose? Because the honest answer to some questions is "it isn't there" — a lookup that might not find.

Step 3: handling both roads


A maybe value may not simply be used as if it were surely there — that is the whole point of marking it. The way to handle it is to ask, with == nothing, and the checker follows the asking: on the road where the answer was yes, the value is known to be nothing; on the other road, it is known to be there, of its kind, and may be used freely. The asking is the unwrapping — there is no other word to memorize:

Step 4: meet the checker


Now watch the checker work. This program is shown, not run, because the checker refuses it before anything runs:


make lookup(name) -> maybe number {
    if name == "Tyler" {
        give 29
    }
}
let b = lookup("Noki")
say b + 1


Line 7: This uses a number or nothing — a value that
may be nothing — where a value that is surely there is
needed, and nothing is the empty value: there is
nothing there to use. Check the value first, like:
if value == nothing { ... } else { ... } — in the
'else', the value is known to be there. I caught this
before the program ran, so nothing ran.


Those are the checker's own words, from a real refusal. Read what it did for you: it read the whole program before running it, found the one line where a maybe value was used as if it were surely there, stopped everything, named the line, explained the problem in plain words, and showed the shape of the fix. That is safety you can feel — not a fence you crash into, but a friend at the door who reads your work and says "this one line, here; walk both roads." The guards stand behind the checker, too: a maybe that somehow slips past every proof and is used while it is nothing is refused at the moment of use, in the same plain words.


This is the Swift half of the promise, arriving early: strength that checks your work before it runs, the way a compiled language's does — while you are still writing as freely as JavaScript. You do not have to choose between the two halves. In Nifla they arrive together.
